# Реализация пользовательских сценариев

Документ фиксирует, как реализованы основные сценарии в актуальной версии приложения.

## Сценарий 1. Создание заказа

### Что делает пользователь

1. Открывает раздел `Заказы`.
2. Нажимает `Создать заказ`.
3. Выбирает изделие, количество, даты.
4. Сохраняет заказ.

### Что происходит в системе

- `POST /api/orders` создает запись в `orders`.
- На backend запускается генерация операций по рецепту (`planning.py`).
- Создаются записи `operations` с назначением сотрудников и оборудования.
- Статус заказа пересчитывается автоматически.

## Сценарий 2. Склад и приход

### Что делает пользователь

1. Добавляет новый ингредиент.
2. Выполняет приход на склад.

### Что происходит в системе

- `POST /api/ingredients` создает ингредиент.
- `POST /api/ingredients/{id}/receive` увеличивает остаток и рассчитывает `expiry_date`.

## Сценарий 3. Просмотр календаря

### Что делает пользователь

1. Открывает раздел `Календарь`.
2. Просматривает операции по дням месяца.
3. Переключает месяцы.

### Что происходит в системе

- UI получает данные из `GET /api/operations`.
- Операции группируются по дате старта.
- Активные операции (по текущему времени) подсвечиваются.

## Сценарий 4. Запуск планирования

### Что делает пользователь

1. В календаре нажимает `Запустить планирование`.

### Что происходит в системе

- `POST /api/planning/run` выполняет перепланирование на backend.
- Для заказов пересобираются операции.
- Обновляются статусы ресурсов и заказов.
- UI перезагружает данные.

## Сценарий 5. Настройки ресурсов

### Что делает пользователь

- Меняет статус сотрудника/оборудования.
- Удаляет сотрудника/оборудование.

### Что происходит в системе

- `PATCH /api/employees/{id}/status`
- `PATCH /api/equipment/{id}/status`
- `DELETE /api/employees/{id}`
- `DELETE /api/equipment/{id}`

При удалении связанных ресурсов удаляются соответствующие операции, после чего статусы заказов пересчитываются.
